# 剧情怎么变成「能玩的东西」

## 一句话模型

> **一句剧情 = 一个节点 = 一次触发 + 一次界面反应**

你现在写的所有剧情，只要拆成这三样，就能接进去。

---

## 一个节点要写清 4 件事

| 要素 | 意思 | 例子 |
|---|---|---|
| **谁在说 / 哪来的** | 是 KKT、短信、通知还是系统 | KKT · 组长老师 |
| **内容** | 台词 / 通知文字 / 日程 | 「那还去吃吗？」 |
| **玩家能做什么** | 打字回复 / 点开某 App / 点地点卡 / 什么都不用做 | 自由输入 |
| **做完之后，手机有什么变化** | 新通知 / 红点 / 某个 App 多一条记录 | 钱包通知 · 7-Eleven ¥1,180 |

只要这 4 格填了，我就能接。

---

## 写作模板（直接抄）

```
【节点】N05 取消晚餐
【来源】KKT · 组长老师
【她说什么】那还去吃吗？
【玩家能做什么】自由打字
【玩家可能的几种回应】
  - 太晚了，先回去        → 她回：好。到酒店告诉我。
  - 有点累                → 她回：嗯。回去早点休息。
  - 还是想去，但有点累     → 她回：那先休息一下，等会儿再决定。
【做完的变化】
  - 手机弹出：Apple 钱包 23:41 · 7-ELEVEN ¥1,180
  - 短信里出现「海外用卡通知」
```

---

## 为什么这样拆就能互动

因为网页里只有四种「玩家动作」：

1. **打字** → 系统判断意思 → 对方回话
2. **点通知** → 收起通知 / 记录已读
3. **点 App 里的东西**（照片、地点卡、条目）→ 记录状态
4. **进出 App** → 记录「看过」

你写的每个节点，只要说清「玩家做哪个动作」「做完发生什么」，就能接上。

---

## 你需要额外标注的只有两类

### 1. 选项的「意思」而不是「原文」

不要写「必须回 X」，而是写「这句话的意思是：取消 / 犹豫 / 反问」。

系统按**意思**判断，玩家写什么都能接。

### 2. 哪些是「固定事实」

比如「演出已经结束」「便利店消费已经发生」——这些不能改。
其余的（去不去、发不发地点、接不接受）才允许玩家改变。

---

## 我这边怎么把它变成能玩的东西

```
你写的节点
   ↓
写进 flow.js 的 STEPS（节点表）
   ↓
玩家打字 → intent.js 判断意思 → 选对应的回复
   ↓
节点带的通知 → notify.js 排队 → 8-15 秒后弹出
   ↓
节点带的红点 → 对应 App 图标右上角亮起
   ↓
玩家打开那个 App → 红点消失
```

这些基础设施**已经有了**，你只管写节点。

---

## 建议的写法：一次只写 3 个节点

写多了我接不过来，也容易漏。按这个节奏：

```
写 3 个节点 → 我接 → 你走一遍 → 有问题当场改 → 再写 3 个
```

---

## 现在还差什么（接剧情前要补齐的）

1. **返回按钮统一**：每个 App 点左上角都回桌面，不乱跳
2. **红点统一**：每 App 都有「未读」状态
3. **通知都能点**：点了只收起，不强制跳转

这三样补完，你写的节点接进去就不会「点了没反应」。

---

## 一句话总结

> 你不用管代码。你只要把剧情写成「谁说的 / 玩家能做什么 / 做完手机怎么变」，
> 剩下的判断、推送、红点、存档，都已经是现成的。
